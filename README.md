# 客户案例 HTML 对客展示精修与多轮重部署（HTML Case Refine & Redeploy Skill）

## 一句话简介

将已有客户案例 HTML 页面，在不伪造素材的前提下，快速对齐指定模板视觉语言，清理内部痕迹，支持基于截图与文字说明的多轮微调，并在每一轮自动生成可回滚版本目录与可访问部署链接，帮助售前 / 客户成功同学沉淀稳定可复用的对客展示页。

## 核心能力 / 功能特性

本 Skill 聚焦在「已有页面精修与可复用化」，而不是从零设计网页。它的核心能力可以概括为几类。

第一，将现有客户案例 HTML 页面整体改造成“看起来属于同一套模板体系”的视觉风格，例如某办公协作产品的客户案例模板、客户自有品牌模板、深色一页纸模板等。通过统一背景、色板、字体层级、栅格结构和卡片语言，让页面一眼看上去“是一个体系”的。

第二，在风格对齐的同时，系统性清理所有不适合对客展示的“内部制作痕迹”，例如内部备注、占位标记、校准说明等，只保留对外友好的文案与结构。

第三，支持多轮“截图圈选 + 文字说明”驱动的精细微调。每轮只改动必要的局部区域，避免整体结构被破坏，同时保持节奏快、可验证、可回滚。

第四，为每一轮修改生成独立的版本目录与入口 HTML 文件，并输出可访问的部署链接，便于投屏、截图放入方案或直接发给客户预览。

第五，支持在条件允许的情况下，从真实网页或用户提供的素材中抽取图片并接入页面，严格记录来源，保证素材可追溯，不凭想象“补图”。

## 适用场景

这个 Skill 面向典型的 B2B SaaS 售前、客户成功、解决方案岗位，尤其适合以下场景。

当你已经有了一份客户案例 HTML 页面，但视觉风格比较“工程化”，希望统一为某个品牌模板或一页纸模板，方便对外投屏或截图进方案时，可以使用本 Skill 进行风格重制与对客精修。

当你需要针对同一个客户案例做多轮对齐：第一轮按模板统一风格，后续根据销售、客户成功或客户方反馈进行局部微调（例如标题单行、图片上移、布局收紧、底部补齐等），并希望每一轮都能生成新的部署链接用于复核与流转时，可以用本 Skill 建立稳定可回滚的迭代流程。

当你需要从公开网页、新闻稿、客户自有资料中接入一两张真实图片，强化案例的可信度，又希望整个流程有“素材来源可追溯”记录、避免在对客资料中使用来历不明的图片时，本 Skill 内置的素材接入步骤可以提供帮助。

## 输入内容

为了运行稳定可复用的工作流，本 Skill 假定输入分为“必选输入”和“可选输入”两类。

必选输入包括两部分。第一，原始 HTML 页面或目录。你可以提供一个可直接在浏览器中打开的单个 HTML 文件，也可以提供一个包含入口 `index.html` 与静态资源（例如 `assets/` 目录）的完整页面目录。Skill 会在此基础上创建用于迭代的版本化目录。第二，参考模板至少一种。可以是 PPTX、PDF、可读文档（如 docx、Markdown）、图片截图（模板页或品牌手册截图）等。也可以是在线文档链接，但若运行环境无法访问该链接，将触发阻塞流程，需要你改为提供可下载文件或截图。

可选输入主要用于提高完成度和协作效率。其一，多轮反馈材料，包括标注了圈选区域的截图以及对应的文字说明，用于驱动细节微调。其二，真实素材来源，如网页链接、图片直链或用户上传的图片文件，用于在页面中嵌入客户照片、产品截图、媒体报道配图等，前提是这些素材可以被可靠地获取和记录来源。

## 输出内容

每一轮迭代，Skill 都会产出三类交付物，它们共同构成一个可以积累和复用的资产体系。

第一，本地可复用的页面目录。推荐命名类似 `deploy_<case>_vN/`，其中 `<case>` 为案例标识，`N` 为当前版本号，从 1 递增。目录内至少包含 `index.html` 和必要的静态资源目录（例如 `assets/`）。所有样式、图片等都尽量使用相对路径，确保在不同部署环境中也能轻松迁移。

第二，最新部署链接。每一轮调整完成后，会提供一个可在浏览器中直接访问的 URL，用于投屏、截图或对客分享。同时会建议在访问链接时附带防缓存参数（如 `?v=20260505-1953` 的时间戳形式），并通过强制刷新避免浏览器缓存导致的旧版本残留。

第三，变更说明。变更说明面向售前 / 客户成功协作场景，一般采用“三段式”结构：本轮改了什么、为什么这次这样更适合对客展示、下一轮希望你确认或补充什么。变更说明文本本身不出现在对客页面里，而是用于团队内流转和版本管理。

## 使用方式与典型触发语

本 Skill 适合部署在任意支持“自定义 Skill / 工具”的智能助手、对话式 Agent 或自动化工作流平台中。你可以在平台配置中将 `user_skills/html-case-refine-redeploy` 作为一个模块引入，并将原始 HTML、模板文件等资源挂接到对应的参数上。

在具体使用时，可以通过自然语言直接触发。例如，可以这样说明你的诉求：

```text
按这个模板把我的客户案例 HTML 重制一版，页面要适合对客投屏展示。
```

也可以从“对客精修”的诉求切入：

```text
这个 HTML 页面只适合内部看，帮我按这个参考模板重制成对客展示版本，并清掉所有内部备注、占位提示。
```

在进入多轮迭代阶段时，可以结合截图进行更细致的指令：

```text
我会发几张截图，每张都圈了需要改的地方。请每轮根据截图和说明，只调整对应区域，改完重新部署一版并告诉我变更点。
```

对于需要接入真实图片素材的场景，可以补充说明来源和预期位置：

```text
从这个新闻链接里抓一张主图，作为案例页中的配图放在客户介绍区域，注意记录图片来源和原始 URL。
```

## 工作流说明

本 Skill 的标准工作流可以理解为一条从“确定版本基线”到“最终对客交付”的流水线。下述步骤在概念上是线性的，你可以根据实际平台能力映射为若干子任务或节点。

第零步，建立可迭代的交付结构。在不修改原始输入的前提下，为每次重制创建独立的工作目录。例如，若输入是单个 HTML 文件，可以新建 `deploy_<case>_v1/`，将入口文件命名为 `index.html` 并放入其中；若输入是目录，则复制一份作为版本一的基线。此后所有改动都在最新版本目录上进行，必要时可以复制生成 `v2`、`v3` 等版本，确保随时可回滚。

第一步，获取并解析参考模板，形成“风格简报”。对于 PPTX、PDF 或页面截图，可以直接从视觉结果中提炼出背景色、文字层级、栅格结构、卡片形态、品牌区处理方式等信息；对于在线文档，需要在确认链接可访问的前提下再行解析。如果遇到权限、验证码等问题导致模板无法访问，应立即中止设计步骤，改为输出阻塞说明并请求你提供可读文件或截图。风格简报本身一般以文字形式呈现在变更说明或工作流日志中，用于对齐后续决策。

第二步，按模板做风格对齐重制。基于风格简报，统一页面的设计 Token，例如背景色、主辅色、圆角半径、阴影策略和卡片间距等，并优先重构页面的关键结构，包括顶部标题区、核心指标卡、主叙事卡片、客户原声区以及底部收束区域。这一步追求的是“归属感”而不是绝对像素级还原，只要一眼可以看出属于同一模板体系即可。

第三步，对客文案清理。系统性扫描页面中不适合对外展示的内容，例如“内部备注”“终版校准”“模板待补充”“TODO”等，以及类似说明性文本，并将其移除或替换为中性对外表达。例如，统一使用“客户案例”“Customer Story”等辅助文案，必要时直接移除与客户无关的占位提示。确保对客版本中不再出现内部制作痕迹。

第四步，进入“截图驱动微调 + 实时重部署”的循环。这是工作流的核心阶段。每一轮首先读取你提供的截图和文字说明，将其翻译成可执行的改动点，明确是文字、样式、布局还是素材层面的调整，然后在保持最小改动原则的前提下实施修改。修改完成后，在本地快速检查页面是否存在溢出、错位或可读性问题，再部署到在线环境，并生成新的版本目录和访问链接。

第五步，真实素材接入（如有）。当需要从外部网页接入图片时，先记录原始页面 URL 和目标图片 URL，并在可访问的前提下下载到当前版本的 `assets/` 目录中，使用语义清晰的文件名。页面中引用时优先使用相对路径。若目标网页因登录、验证码或防爬机制无法访问，则应停止该素材接入分支，给出清晰的阻塞说明，并建议你改用上传文件或截图的方式提供图片。

第六步，最终交付检查。当模板风格、文案清理和多轮微调都完成后，需要再做一次整体检查，确认视觉风格统一、结构完整、对比度合适、叙事链路连贯（例如“背景–方案–价值–客户原声–收束”这一链路），并最终输出最新版本目录、部署链接和总结性的变更说明。

在任意关键输入无法获取的情况下（例如模板链接不可访问、素材无法下载等），工作流应立即切换到“失败处理与阻塞报告”路径，不继续生成新的对客页面，而是向你说明阻塞点、已尝试手段、影响范围以及可执行的下一步建议。

## 边界与限制

本 Skill 只在“已有 HTML 页面 + 可读模板 + 可用素材”的前提下工作，不负责从零发明客户故事或凭空创造网页结构。它不会主动生成虚构的品牌 LOGO、人物照片或客户评价，也不会在没有任何依据的情况下补写内容。所有外部图片和文案必须来自真实可追溯的来源，例如你提供的文件、网页链接或截图。

Skill 假定运行环境尊重网站的访问规则，不会尝试绕过登录、验证码或防爬机制。如果目标网页无法在当前环境中访问，就视为不可用输入，需要你改为提供文件或截图。这一点对于包含敏感或受限内容的站点尤为重要。

此外，本 Skill 聚焦在前端展示层面的精修，不包含后端服务、数据库或复杂交互逻辑。部署方式可以根据你的平台自行选择，例如静态文件托管、内置预览服务等。Skill 本身只要求每轮输出一份可本地存档的目录和一个可在浏览器中打开的链接。

最后，需要强调的是，这套工作流提供的是一条“可落地、可复用”的基线，无法替代专业视觉设计团队在品牌体系、插画风格等高阶维度上的决策。如果你的场景对品牌调性有更高要求，可以把本 Skill 当作助理工具，用来快速出对客版本，再由设计师进一步精修。

## 示例用法

下面给出一个抽象示例，方便你理解如何在自己的 Agent / 工作流平台中使用本 Skill。

场景一：你已经有一个名为 `acme_case.html` 的客户案例页面，以及一份客户认可的案例模板 PPT。你可以在平台上上传这两个文件，然后向智能助手发送类似这样的指令：

```text
这里有一个客户案例 HTML 页面 acme_case.html 和一个模板 PPT，帮我按模板重制一版适合对客展示的页面，并输出第一版部署链接。
```

Skill 会按前述工作流生成 `deploy_acme_v1/` 目录、内部 `index.html` 文件以及部署链接，并返回一段说明本轮做了哪些改动。

在你查看 v1 之后，可能会发现一些细节需要微调，例如“标题要单行”“右侧品牌区略显空，可以收紧一些留白”。此时可以补充截图与说明：

```text
这是 v1 的截图，图中圈出来的标题区希望调整为单行显示，右侧品牌区整体上移一些，避免留白过多。请基于当前版本生成 v2，改动范围只局限在标题区和品牌区。
```

Skill 会在现有版本基础上复制出 `deploy_acme_v2/`，完成调整后再次部署，并向你说明本轮具体改了哪些地方、为什么这样更适合对客展示。

如果你还希望接入真实素材，例如某媒体报道中的配图，可以追加指令：

```text
从这篇报道页面中选取一张主图，放在案例的“客户介绍”区域，用作配图。无法访问网页时不要自行生成图片，直接告诉我阻塞原因。
```

如果网页可访问，Skill 会下载图片存入当前版本的 `assets/` 目录，并在变更说明中记录图片来源；如果网页不可访问，则会停止该步骤并提示你改用截图或文件上传的方式提供素材。

## 目录结构（建议）

为了方便在 GitHub 等代码托管平台上维护，本 Skill 建议使用类似下面的目录结构。实际项目中可以根据需要增删文件，但整体思路保持不变。

```text
.
├── README.md
└── user_skills/
    └── html-case-refine-redeploy/
        ├── scripts/
        │   ├── bump_version_dir.py
        │   ├── scan_internal_copy.py
        │   └── download_asset.py
        └── references/
            └── micro_tuning_patterns.md
```

其中，`scripts/` 下的脚本用于辅助创建版本目录、扫描内部文案、下载外部图片等；`references/` 中可以放置微调模式速查表、模板示例说明等文档。Skill 的核心逻辑与流程说明，则可以继续放在当前 Skill 目录下的文档中，供有需要的开发者查阅。
